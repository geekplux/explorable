Why ropes beat strings for big edits

By Ada Example, March 2024

Text editors spend most of their time doing small edits in the middle of large files. A plain string makes every one of those edits expensive, because inserting a character means copying everything after it.

The idea

A rope stores the text as a balanced binary tree whose leaves hold short chunks of characters. Each inner node remembers the length of its left subtree, which is enough to find any position by walking down from the root.

To insert text, you split the leaf at the cursor and hang a new leaf in between. Only the nodes on one path from the root change, so the cost grows with the logarithm of the file size instead of the file size itself.

When it pays off

For a short note, a string is simpler and just as fast. Once files reach megabytes, the copy cost dominates, and a rope keeps every keystroke cheap. Concatenation also becomes a single new node, which makes undo history cheap to keep around.

  • Insert and delete in O(log n) time instead of O(n).
